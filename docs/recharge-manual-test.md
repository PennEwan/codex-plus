# CDK 充值插件：桌面 App 手动测试清单

目标：在官方 Codex 桌面 App（26.1013.4894.0，内核 0.163.0-alpha.10.2）中验证 `/充值` 入口，以及 CLI 实测无法覆盖的界面表现。后台为本机模拟后台（真实后台尚不存在）。

## 前置条件
- 模拟后台已在运行：`python scripts\mock_recharge_server.py`，并已执行 `cdkr.cmd config --base-url http://127.0.0.1:18787`（窗口底部会显示"当前连接的是本机模拟后台"）。
- 双击 `cdkr.cmd status`（或命令行运行）应看到 `插件：已安装`、`Hook 状态：trusted`。

## 步骤

| # | 操作 | 预期 | 请记下 |
|---|---|---|---|
| 1 | 完全退出并重新打开 Codex App → 插件 → Codex CDK 充值 → 点「信任」 | 信任后 `cdkr.cmd status` 显示 trusted | 信任按钮在哪、叫什么 |
| 2 | 在任意会话输入框单独发送 `/充值` | 约 1–5 秒内弹出「Codex 充值」小窗口；这条消息不发给模型（没有模型回复） | 输入 `/` 时是否弹出斜杠菜单、能否正常发送；对话里显示了什么（拦截原因文字？）；窗口是否在最前 |
| 3 | 窗口里确认账号邮箱是你的 Codex 账号 → 点「确认充值到此账号」 | 显示"绑定成功" | — |
| 4 | 输入 `TEST-OK01` → 回车 | 绿色"充值成功"，输入框清空 | — |
| 5 | 再输入 `TEST-OK01` → 确认兑换 | "重复兑换……未重复扣除" | — |
| 6 | 输入 `WRONG-1234` | 红色"CDK 无效" | — |
| 7 | 关掉模拟后台（Ctrl+C），输入 `TEST-OK02` | 红色"网络连接失败，兑换请求没有发出，CDK 未使用" | — |
| 8 | 窗口开着时，回到 Codex 再发送一次 `/充值` | 不会出现第二个窗口，已有窗口回到最前 | — |
| 9 | 关闭充值窗口，在 Codex 里正常发一条消息 | Codex 不受影响，正常回复 | 发送普通消息时是否感到变慢 |
| 10 | 发送 `/充值 ABCD-TEST` | 同样被拦下，并提示不要把 CDK 写在 /充值 后面 | 对话历史里是否还能看到这条消息；之后 App 自动生成的标题 / 建议里是否出现 `ABCD-TEST` |
| 11 | 输入 `TEST-SLOW`，在"正在兑换…"时点窗口的关闭按钮 | 弹出确认框；选"否"窗口保留，约 20 秒后显示成功 | — |
